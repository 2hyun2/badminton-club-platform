# ALL IN SHUTTLECOCK (AIS)

> 운영은 더 쉽게, 배드민턴은 더 즐겁게.

여러 배드민턴 동호회가 회원·게스트·출석·경기·기록·레슨·회비 | 정산과 공개 홈페이지를 관리하고, 회원은 자신의 동호회 생활을 편하게 확인하는 웹·앱 서비스의 기획 및 설계 저장소입니다.

현재는 Next.js 웹 UI를 먼저 만들며 핵심 흐름을 검증하는 단계입니다. 실제 결제나 출시된 서비스가 아닙니다.

## 서비스가 풀려는 문제

- 회원은 여러 동호회에 소속될 수 있는데, 출석·경기·기록·회비 정보는 동호회마다 흩어져 있습니다.
- 운영자는 회원 상태, 경기 진행, 회비, 게스트, 1:1 레슨 일정을 단체 채팅과 수기 장부로 함께 관리하기 어렵습니다.
- 앱을 쓰지 않는 방문자도 게스트로 운동을 신청하고 결과를 확인할 수 있어야 합니다.

AIS는 동호회별 운영 공간을 제공하되, 회원이 여러 동호회를 자연스럽게 오갈 수 있게 설계합니다.

## 핵심 기능 방향

| 영역 | 기능 |
| --- | --- |
| 다중 동호회 | 동호회 만들기, 가입 신청·승인, 여러 동호회 선택·전환 |
| 회원·운영 | 회원 등급·권한·상태, 출석·퇴장, 회원 목록과 랭킹 |
| 경기 | 단식·복식, 일반전·친선전, 실시간 상태, 결과·ELO·전적 |
| 게스트 | 공개 동호회 탐색, 게스트 참가 신청·승인, 접근 코드 기반 신청 내역 확인 |
| 동호회 홈페이지 | 동호회 소개, 공지, 일정, 가입 안내를 담는 보급형 공개 홈페이지 |
| 1:1 레슨 | 코치별 시간 단위 레슨 개설, 회원 신청, 운영진 승인, 예약 목록 |
| 회비 \| 정산 | 수동 회비 청구, 입금 처리, 레슨비 차감, 환불·정정, 미수금 관리 |

## 핵심 설계 결정

- 앱 회원(`User`)과 동호회(`Club`)는 별개이며, `Membership`이 둘을 연결합니다. 등급·권한·레이팅·정산은 동호회별로 분리됩니다.
- 로그인 뒤에는 항상 동호회 선택 화면을 먼저 보여 줍니다. 마지막 동호회로 자동 진입하지 않습니다.
- 초기 계정 생성·로그인은 카카오, Google, Apple 소셜 로그인만 사용합니다. 아이디·비밀번호 로그인은 제공하지 않습니다.
- 게스트 신청은 정식 동호회 가입과 별개입니다. 비회원도 신청할 수 있으며, 승인되어도 동호회 회원이 되지는 않습니다.
- 정산은 실제 결제 기능이 아닙니다. 운영진이 실제 입금을 확인한 뒤 수동으로 기록하는 동호회별 장부입니다. 잔액이 음수이면 미수금으로 표시하며, 경기·레슨 참여는 막지 않습니다.
- 코치는 동호회 회원이거나 이름만 등록된 외부 초빙 강사일 수 있습니다. 레슨 신청 승인·거절은 운영진만 처리합니다.
- 먼저 웹에서 핵심 UI와 흐름을 검증하고, 이후 React Native 앱 외관과 푸시 알림을 확장합니다.

## 기술 방향

```text
Web: Next.js
API: Node.js + Express + Socket.IO
Database: PostgreSQL
Mobile: React Native (웹 핵심 흐름 검증 뒤 확장)
Infrastructure: AWS (서울 리전 검토)
```
